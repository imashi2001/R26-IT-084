# API Contract: Event-Aware Waste Demand Forecasting Component

This document details the exact API contract for all endpoints belonging to the **Event-Aware Waste Demand Forecasting** component in this repository. All information is cited directly from backend route handlers, repository files, and frontend consumers.

In [`backend/routes/index.js`](file:///c:/Reasearch/SLIIT/R26-IT-084/backend/routes/index.js), the forecasting routes are mounted onto the Express gateway as follows:
* Line 53: `router.use("/api/waste-data", wasteDataRoutes);`
* Line 54: `router.use("/api/waste-trend", wasteTrendRoutes);`
* Line 55: `router.use("/api/waste-insights", wasteInsightsRoutes);`
* Line 56: `router.use("/api/waste-entries", wasteEntriesRoutes);`

A repository-wide search confirms that **no other routes** in the backend execute Python scripts, invoke `retrain_pipeline.py`, or interact with `waste_forecast/src/daily_forecast.py`.

* **Query Parameters:**

## 4. Architectural & Implementation Anomalies

1. **Unvalidated Query Dates on Forecast Endpoints:**
   * In [`backend/routes/wastedata.routes.js:L73`](file:///c:/Reasearch/SLIIT/R26-IT-084/backend/routes/wastedata.routes.js#L73) and [`backend/routes/wastetrend.routes.js:L94`](file:///c:/Reasearch/SLIIT/R26-IT-084/backend/routes/wastetrend.routes.js#L94), `req.query.date` is accepted without date-format regex validation.
